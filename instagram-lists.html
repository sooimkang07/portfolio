Instagram · Product Design · Concept · 2025

Fitting a new control layer into Instagram

Role
Solo Product Designer
Timeline
7 weeks · Nov–Dec 2025
Platform
Instagram · iOS Concept
Scope
Research · Systems Design · Hi-Fi Prototype

01 / Overview

One feed forces every relationship to compete.

Instagram ranks every relationship in one feed. That works for discovery, but not for how people actually hold their social graph.

Problem

Friends, creators, brands, and communities share one ranking. Users scroll a long time without seeing the people they meant to check on.

Opportunity

As private sharing grows and broad posting declines, the gap isn't better prediction. It's letting users set priority in the moment.

How might users choose which relationships matter now, without losing discovery?

02 / Solution

Lists: users pick the context, Instagram ranks within it.

Users choose who they're browsing for. Ranking handles the rest.

One list reshapes every surface

Home, Stories, and Following adapt to the selected list.

03 / Visual system

New states, built from Instagram's existing visual language.

Logo morphs, list icons, Stories filtering, and deck animations.

04 / Core Flows

Lists had to live inside browsing, not beside it.

Lists only works if creating, switching, and editing feel like browsing. Every flow cuts setup cost and keeps context visible.

Defaults deliver value on day one

All, Following, and Close Friends work immediately, with no organizing from scratch.

Custom lists extend existing mental models

School, brands, sports, food: users make explicit the groups already in their heads.

Creation happens where intent emerges

Create a list from Home, profiles, posts, Stories, Following, or the lists view, wherever the need appears.

Editing happens inside normal browsing

Edit from posts, Stories, profiles, Following, and list views. Organizing stays lightweight, not administrative.

05 / System

A shared context state, not a new destination.

Lists adds no new destination. One context state shapes Home, Stories, profiles, and Following at once.

Before Lists

Every surface reads the full follow graph, so all relationship contexts compete in one ranking pool.

With Lists

One active list narrows the pool. Home, Stories, and Following respond to the same state.

Lists changes how existing surfaces interpret priority, without adding another isolated tool.

06 / Research

Algorithms infer relevance. Only users know intent.

Users already sort who they follow into relationship groups. What's missing is a way to declare priority in the moment.

Relevance is not priority

Behavioral signals estimate what matters generally, not who matters right now.

Retrieval, not volume, is the problem

Users weren't just overwhelmed. They were missing the people they meant to see.

The feed collapses different social contexts

Friends, creators, brands, and communities rank together despite serving different goals.

08 / Design Decisions

Extend Instagram's patterns instead of inventing new ones.

The key calls were system fit, persistence, and low-friction upkeep. Users shouldn't have to learn a new product model.

Structural fit

Lists plugs into Instagram's existing flow. Creating, switching, filtering, and editing span Home, Stories, profiles, posts, and Following.

Keep context visible

Lists sit in the main rail, so switching context is part of browsing, not a settings trip.

Make state persistent

A filter that resets is a utility. Persistent state makes context a real navigation mode.

Visual fit

No new interaction model. Lists reuses Instagram's badges, chips, and Close Friends-adjacent patterns.

Build on familiar visual language

Icons extend Close Friends and existing list metaphors, not a new visual system.

Support lightweight maintenance

Editing lives in context, not an admin flow.

09 / Reflection

Users define context. Algorithms define relevance.

I shifted from improving feed screens to restructuring the prioritization beneath them. Understand relationships before optimizing engagement.

Context before ranking

Relevance only works once context is defined.

Shared responsibility

Users choose who matters; algorithms rank what matters within that set.

System-level product thinking

Not a feature layer: a scalable model where user intent and algorithmic relevance work together.
