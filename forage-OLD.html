Forage · Wearable + AI · 2026

Turning fleeting inspiration into reusable design assets

Role
Product designer · Systems thinking
Timeline
8 weeks
Scope
0→1 product definition · Hardware · Web app
Focus
Capture-to-retrieval system for design inspiration

01 / Overview

Designers notice inspiration, then lose it before reuse.

Designers spot usable moments in the world, then lose them before they become material. Forage captures in context, turns raw input into structured assets, and treats retrieval as a core behavior.

Problem framing — fleeting moments vs. structured assets

The capture problem

Inspiration strikes mid-movement or in passing, too fast for manual capture. A wearable makes saving fast enough to happen in the moment.

The translation problem

Raw captures are generic photos or notes. AI translates them into usable asset types: images, color, typography, and motion.

The retrieval problem

Saved fragments are organized by file, not intent. Indexing by type and recency keeps them reusable, not lost in a camera roll.

02 / Solution

The ring is the entry; the system is the value.

Forage is a pipeline: capture in context, translate into design objects, organize into a library, and retrieve while building.

System architecture — Sense → Capture → Translate → Organize → Reuse

Ring capture

A minimal ring interaction saves moments without breaking flow, away from a desk.

AI translation

AI sorts captures into four asset types and extracts reusable properties: dominant colors, typography, image subjects, animation references.

Structured library

A web app organizes captures by type and recency, so designers can browse, filter, and inspect them.

03 / Core Flows

Capture alone isn’t the story; reuse is.

The full flow: capture → interpretation → retrieval → reuse.

Capture in context

A designer spots a relevant moment and saves it with a minimal ring interaction. Speed and low disruption are the point.

Ring capture mockup

AI turns moments into design objects

The system classifies each capture and adds type-specific metadata: images, color palettes, typography traits, or animation references.

AI translation UI

Browse and retrieve

The web app works like a personal inspiration channel: scan by recency, filter by type, inspect in detail.

Web library browse interface

Reuse inside creative work

Designers return to the library when building brand systems, moodboards, or motion studies. Captures become inputs to real work.

Reuse in design workflow

04 / System

Forage works because it’s a pipeline, not a feature.

The value isn’t in any single screen. It’s in how wearable input, AI interpretation, data structure, and retrieval reinforce each other.

System diagram

Capture → Translation

Hardware lowers interaction cost; AI does the sorting a designer would otherwise do later.

Organization → Retrieval

Indexing by type and recency makes captures findable when needed, not buried in photo libraries.

Retrieval → Reuse

Treating the library as a core behavior closes the loop back into creative work.

05 / Design Decisions

Every decision narrowed the concept until it cohered.

Each decision answered a point where the system was breaking or unclear.

Narrow to four output types

"Capture anything" is broad but weak. Limiting it to images, color, typography, and motion made it teachable, buildable, and coherent.

Ring as low-friction entry point

The wearable only works if it cuts interaction cost. Inspiration often hits mid-movement or in social settings where opening an app is too disruptive.

AI as translation infrastructure

AI is infrastructure, not a gimmick. It does the structural work: classify, extract, organize, and prepare captures for reuse.

Make retrieval as important as capture

Many concepts stop at acquisition. Forage treats the web app as a repository with type filters, recency sorting, and browsable structure.

Design decision framework

06 / Reflection

The product is the pipeline, not the ring.

Product definition over object design

The ring isn’t the strongest part. Finding the break between noticing and reuse, and designing a pipeline across it, is.

Retrieval as a first-class behavior

Most speculative concepts stop at capture. Designing retrieval and reuse with equal rigor made the library as important as the wearable.
